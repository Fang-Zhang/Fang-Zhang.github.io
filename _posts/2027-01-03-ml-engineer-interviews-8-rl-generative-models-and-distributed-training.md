## 1. "Formulate a problem as reinforcement learning and explain Q-learning."

**What it tests.** The vocabulary (state, action, reward, discount, policy, value) and the ability to write the update.

**Reference answer.** An agent interacts with an environment: at each step it observes a state, takes an action, receives a reward and moves to a new state; the goal is a policy that maximises the discounted sum of future rewards. The action-value function Q(s, a) is the expected return from taking a in s and acting well afterwards. Q-learning updates it towards a bootstrapped target: `Q(s,a) <- Q(s,a) + alpha * (r + gamma * max_a' Q(s',a') - Q(s,a))`. It is off-policy: the target uses the greedy action, whatever action the agent actually took. [Mnih et al. (2013)](https://arxiv.org/abs/1312.5602) describe their agent as a convolutional network trained with a variant of Q-learning, whose input is raw pixels and whose output is a value function estimating future rewards, applied to seven Atari 2600 games with no change of architecture or algorithm.

A check on a six-state corridor (goal at the right end, reward 1, step cost -0.01, discount 0.9): value iteration gives the optimal values, and Q-learning with epsilon-greedy exploration should converge to the same ones.

```python
import numpy as np
rng = np.random.default_rng(0)
N, GAMMA, STEP = 6, 0.9, -0.01          # states 0..5, goal at 5 (reward +1, terminal); actions 0=left 1=right
def env(s, a):
    s2 = max(0, s - 1) if a == 0 else s + 1
    return (s2, 1.0, True) if s2 == N - 1 else (s2, STEP, False)
V = np.zeros(N)
for _ in range(200):                      # value iteration for the optimal values
    for s in range(N - 1):
        V[s] = max(r + (0 if d else GAMMA * V[s2]) for s2, r, d in (env(s, a) for a in (0, 1)))
Q = np.zeros((N, 2)); alpha, eps = 0.1, 0.2
for ep in range(2000):
    s = 0
    for _ in range(100):
        a = rng.integers(2) if rng.random() < eps else int(Q[s].argmax())
        s2, r, d = env(s, a); Q[s, a] += alpha * (r + (0 if d else GAMMA * Q[s2].max()) - Q[s, a]); s = s2
        if d: break
print("value iteration V*:", np.round(V[:-1], 3)); print("Q-learning max_a Q:", np.round(Q[:-1].max(1), 3)); print("greedy policy (1 = right):", Q[:-1].argmax(1))
```

```
value iteration V*: [0.622 0.702 0.791 0.89  1.   ]
Q-learning max_a Q: [0.622 0.702 0.791 0.89  1.   ]
greedy policy (1 = right): [1 1 1 1 1]
```

The learned values match the optimal ones to three decimals even though 20% of the actions were random, which is the off-policy property at work. The values fall by a factor of 0.9 per step away from the goal, as the discount implies (0.622 is 0.9^4 = 0.656 less the accumulated step costs).

**Common weak answer.** "The agent learns by trial and error." It names no state, reward or update.

**Follow-up.** "What is the difference between on-policy and off-policy?" Off-policy methods learn about one policy (the greedy one) from data generated by another; on-policy methods learn about the policy that generates the data.

## 2. "How do you balance exploration and exploitation?"

**What it tests.** Understanding that pure greedy behaviour fails, and the standard fix.

**Reference answer.** An agent that always takes the action with the highest current estimate can lock onto a poor action it happened to rate highly early on, and never learns otherwise. The simplest remedy is epsilon-greedy: with probability epsilon take a random action, otherwise the greedy one. The Atari paper's agent follows a behaviour policy of this kind, epsilon-greedy with epsilon annealed during training, and it is the usual starting point; more directed methods exist (the sources read for this post do not cover them).

A simulation on a standard testbed: 2,000 randomly generated 10-armed bandit problems (arm means drawn from a standard normal distribution, reward noise with standard deviation 1), 1,000 steps each, sample-average estimates:

```python
import numpy as np
rng = np.random.default_rng(0); runs, steps = 2000, 1000
q_true = rng.normal(size=(runs, 10)); best = q_true.max(1)
for eps in (0.0, 0.01, 0.1):
    Q = np.zeros((runs, 10)); n = np.zeros((runs, 10)); tot = 0.0; opt = 0.0
    for t in range(steps):
        greedy = Q.argmax(1); rand = rng.integers(10, size=runs); a = np.where(rng.random(runs) < eps, rand, greedy)
        r = q_true[np.arange(runs), a] + rng.normal(size=runs); n[np.arange(runs), a] += 1
        Q[np.arange(runs), a] += (r - Q[np.arange(runs), a]) / n[np.arange(runs), a]
        tot += r.mean()
        if t >= steps - 100: opt += (a == q_true.argmax(1)).mean() / 100
    print(f"epsilon={eps:<5} mean reward per step {tot / steps:.3f}  (best arm's mean averages {best.mean():.3f})  optimal-arm rate in last 100 steps {opt:.2f}")
```

```
epsilon=0.0   mean reward per step 1.025  (best arm's mean averages 1.535)  optimal-arm rate in last 100 steps 0.35
epsilon=0.01  mean reward per step 1.210  (best arm's mean averages 1.535)  optimal-arm rate in last 100 steps 0.61
epsilon=0.1   mean reward per step 1.303  (best arm's mean averages 1.535)  optimal-arm rate in last 100 steps 0.81
```

The greedy agent finds the best arm in only 35% of the problems; with epsilon = 0.1 it does so in 81% and earns more per step (1.303 against 1.025). With epsilon = 0.01 it starts more slowly and is still catching up at step 1,000 (left panel of the figure). The best epsilon depends on the horizon: a small value wins only if there are enough steps.

**Common weak answer.** "Use epsilon-greedy." Correct, and it skips why greedy fails and how to choose epsilon.

**Follow-up.** "How would you reduce epsilon over time?" A decaying schedule explores early and exploits later; the right rate is tuned on the problem.

## 3. "Why does DQN use experience replay, and what is the overestimation problem?"

**What it tests.** Knowing why deep RL is unstable and one concrete bias.

**Reference answer.** Consecutive transitions from one trajectory are strongly correlated, and the data distribution shifts as the policy changes. The Atari paper alleviates both by storing past transitions and training on random samples of them: experience replay, which smooths the training distribution over many past behaviours. (Later work adds a separate target network; the paper read for this post, from 2013, does not include one.)

The overestimation problem comes from taking a maximum over noisy estimates. [Fujimoto et al. (2018)](https://arxiv.org/abs/1802.09477) note that function approximation errors in value-based methods such as deep Q-learning are known to cause overestimated values and suboptimal policies, show that the problem persists in actor-critic methods, and respond with an algorithm built on Double Q-learning that takes the minimum value between a pair of critics, plus delayed policy updates (TD3). The mechanism is easy to see: if all actions are truly worth 0 but the estimates are noisy, the maximum of the estimates is positive.

```python
import numpy as np
rng = np.random.default_rng(0); n = 200000
for k in (2, 10, 100):
    est = rng.normal(size=(n, k)); est2 = rng.normal(size=(n, k))      # k actions, all with true value 0, estimates have noise std 1
    single = est.max(1).mean(); dbl = est2[np.arange(n), est.argmax(1)].mean()
    print(f"{k:3d} actions: max of noisy estimates {single:+.3f} | double estimator {dbl:+.3f} (true value 0)")
```

```
  2 actions: max of noisy estimates +0.566 | double estimator -0.002 (true value 0)
 10 actions: max of noisy estimates +1.538 | double estimator -0.003 (true value 0)
100 actions: max of noisy estimates +2.507 | double estimator +0.000 (true value 0)
```

With 100 actions the maximum of the estimates is 2.5 noise-standard-deviations too high. Selecting the action with one set of estimates and evaluating it with an independent set (the double estimator) removes the bias in this experiment. The bias grows with the number of actions, so it matters most with large action sets.

**Common weak answer.** "Replay saves memory." Its purpose is to decorrelate samples and reuse them.

**Follow-up.** "Why does bootstrapping with a function approximator diverge more easily than in the table above?" Updates to one state change the estimates of others, so errors can feed back through the target; the table has no such coupling. (The author's explanation, not from the sources read.)

## 4. "Explain policy gradients and PPO's clipped objective."

**What it tests.** The difference from value-based methods, and why a trust-region-like constraint is needed.

**Reference answer.** Policy-gradient methods adjust the policy parameters directly to increase expected return, using sampled returns weighted by an advantage estimate. Subtracting a baseline reduces variance without changing the expected gradient. Taking many gradient steps on the same batch can move the policy too far; [Schulman et al. (2017)](https://arxiv.org/abs/1707.06347) propose proximal policy optimization, which alternates sampling data from the environment with optimising a surrogate objective, and which allows multiple epochs of minibatch updates on each batch, where standard policy gradient methods do one update per data sample. The clipped objective is `min(r_t A_t, clip(r_t, 1 - eps, 1 + eps) A_t)`, where r_t is the ratio of new to old action probabilities and eps = 0.2 is an example value. The paper's motivation: clipping removes the incentive to move the ratio outside [1 - eps, 1 + eps], and taking the minimum makes the objective a pessimistic lower bound that ignores a change in the ratio only when it would improve the objective.

The objective's values, and a baseline-subtracted REINFORCE run on a three-armed bandit:

```python
import numpy as np, torch
eps = 0.2
print("ratio  A    unclipped  clipped  PPO objective min(.)")
for A in (1.0, -1.0):
    for r in (0.5, 0.9, 1.0, 1.1, 1.5):
        u = r * A; c = float(np.clip(r, 1 - eps, 1 + eps)) * A; print(f"{r:4.1f} {A:+.0f}   {u:+8.2f}  {c:+8.2f}  {min(u, c):+8.2f}")
torch.manual_seed(0); logits = torch.zeros(3, requires_grad=True); means = torch.tensor([0.2, 0.5, 0.8]); opt = torch.optim.Adam([logits], lr=0.05)
for step in range(300):
    p = torch.softmax(logits, 0); a = torch.multinomial(p.detach(), 64, replacement=True); r = means[a] + 0.1 * torch.randn(64)
    loss = -((r - r.mean()) * torch.log(p[a])).mean(); opt.zero_grad(); loss.backward(); opt.step()
print("REINFORCE with a mean baseline on a 3-armed bandit (true means 0.2, 0.5, 0.8): final policy", np.round(torch.softmax(logits, 0).detach().numpy(), 3))
```

```
ratio  A    unclipped  clipped  PPO objective min(.)
 0.5 +1      +0.50     +0.80     +0.50
 0.9 +1      +0.90     +0.90     +0.90
 1.0 +1      +1.00     +1.00     +1.00
 1.1 +1      +1.10     +1.10     +1.10
 1.5 +1      +1.50     +1.20     +1.20
 0.5 -1      -0.50     -0.80     -0.80
 0.9 -1      -0.90     -0.90     -0.90
 1.0 -1      -1.00     -1.00     -1.00
 1.1 -1      -1.10     -1.10     -1.10
 1.5 -1      -1.50     -1.20     -1.50
REINFORCE with a mean baseline on a 3-armed bandit (true means 0.2, 0.5, 0.8): final policy [0.002 0.001 0.997]
```

For a positive advantage, the objective stops rewarding a ratio above 1.2 (1.5 gives 1.20, the same as 1.2). For a negative advantage, it keeps penalising a ratio above 1.2 (1.5 gives -1.50, not -1.20) but stops rewarding a ratio below 0.8 (0.5 gives -0.80): it ignores a change only when the change helps. The REINFORCE run concentrates 99.7% of the probability on the best arm.

**Common weak answer.** "PPO clips the gradient." It clips the probability ratio inside the objective, not the gradient norm (a different technique).

**Follow-up.** "Why is an advantage better than a raw return?" It removes the part of the return that does not depend on the action, which lowers the variance of the gradient estimate.

## 5. "Explain the VAE and the reparameterisation trick."

**What it tests.** Latent-variable models, the bound being optimised, and why sampling inside a network needs a trick.

**Reference answer.** A variational autoencoder is a directed latent-variable model: a decoder maps a latent z to data, and an encoder (the "recognition model") approximates the intractable posterior over z. [Kingma and Welling (2014)](https://arxiv.org/abs/1312.6114) train both by maximising a lower bound on the data likelihood, and their first contribution is a reparameterisation of that bound which gives an estimator that can be optimised with standard stochastic gradient methods. The idea: instead of sampling z from N(mu, sigma^2) (which blocks gradients to mu and sigma), sample noise eps from N(0, 1) and compute z = mu + sigma * eps, so z is a differentiable function of the parameters.

The effect on the gradient estimate can be measured. Take z ~ N(mu, 1) and the gradient of E[z^2] with respect to mu, which is 2 mu. The score-function estimator and the reparameterised one are both unbiased; they differ in variance:

```python
import numpy as np
rng = np.random.default_rng(0); mu, n, reps = 1.5, 10, 100000
z = rng.normal(mu, 1, size=(reps, n)); eps = z - mu
score = (z ** 2 * (z - mu)).mean(1)          # score-function estimator of d/dmu E[z^2]
reparam = (2 * (mu + eps)).mean(1)          # reparameterised: z = mu + eps, d(z^2)/dmu = 2z
print(f"true gradient 2*mu = {2 * mu:.3f}")
print(f"score-function estimator (10 samples): mean {score.mean():.3f}, std {score.std():.3f}")
print(f"reparameterised estimator (10 samples): mean {reparam.mean():.3f}, std {reparam.std():.3f}")
```

```
true gradient 2*mu = 3.000
score-function estimator (10 samples): mean 3.008, std 2.272
reparameterised estimator (10 samples): mean 3.002, std 0.632
```

Both centre on the true gradient 3.0. The reparameterised estimator has 3.6 times lower standard deviation with the same number of samples, which is why it is the standard choice when the sampling distribution allows it. It does not apply directly to discrete latent variables, which is a typical follow-up.

**Common weak answer.** "A VAE is an autoencoder with noise." The latent distribution and the bound are the model; the noise is the sampling step.

**Follow-up.** "What are the two terms of the bound?" A reconstruction term, which rewards decoding the data from z, and a divergence term, which keeps the encoder's distribution close to the prior.

## 6. "How does a GAN work, and why are GANs hard to train?"

**What it tests.** The game formulation, and what its failure modes are.

**Reference answer.** [Goodfellow et al. (2014)](https://arxiv.org/abs/1406.2661) train two models together: a generator G that captures the data distribution and a discriminator D that estimates the probability that a sample came from the training data rather than from G. G is trained to maximise the probability that D makes a mistake, so the framework is a two-player minimax game. In the space of arbitrary functions the paper shows a unique solution, with G recovering the data distribution and D equal to 1/2 everywhere; when both are multilayer perceptrons the whole system trains with backpropagation, with no Markov chains or unrolled inference during training or sampling.

Why training is hard: the equilibrium is a game, not a minimum of a fixed loss, so the two networks can oscillate; and when the generator and the data live on low-dimensional manifolds that barely overlap, a discriminator can separate them easily and give the generator little useful signal (the author's explanation). [Arjovsky et al. (2017)](https://arxiv.org/abs/1701.07875) make a related point in the introduction of the Wasserstein GAN paper: the model density may not exist when distributions are supported by low-dimensional manifolds, which is why maximum-likelihood training is problematic there, and they propose a different distance for learning the distribution. The sources read here do not include evaluations of how often these failures occur in practice; the answer should say that the failure modes are known, not that they are universal.

Compare the three families in one sentence each: a VAE optimises an explicit likelihood bound and samples in one pass but tends to give blurrier samples (the author's general statement, not tested here); a GAN has no likelihood and samples in one pass but trains adversarially; a diffusion model (next question) has a stable regression-style loss and samples with many network evaluations.

**Common weak answer.** "The generator tries to fool the discriminator." It stops at the slogan without the objective, the optimum or the failure modes.

**Follow-up.** "How do you evaluate a generative model?" There is no single metric; common choices are sample-quality scores such as the Inception score and FID (which the diffusion paper below reports) and human evaluation, each with limits.

## 7. "How does a diffusion model work?"

**What it tests.** The forward and reverse processes, and the closed form that makes training efficient.

**Reference answer.** A forward process gradually adds Gaussian noise to the data over T steps until it is close to pure noise; a network is trained to reverse it, one step at a time. [Ho et al. (2020)](https://arxiv.org/abs/2006.11239) describe diffusion probabilistic models as latent variable models trained on a weighted variational bound, connected to denoising score matching with Langevin dynamics, and report an FID of 3.17 on unconditional CIFAR-10. Two facts matter for the interview. First, the forward process admits sampling x_t at any step in closed form: with alpha_t = 1 - beta_t and abar_t the product of the alphas up to t, `q(x_t | x_0) = N(sqrt(abar_t) x_0, (1 - abar_t) I)`, so training can pick a random step and noise the data in one shot. Second, the paper sets T = 1000 with variances increasing linearly from 1e-4 to 0.02; sampling therefore needs about a thousand network evaluations.

The closed form can be checked against running the 1,000 noising steps one at a time, on data drawn uniformly from [-1, 1]:

```python
import numpy as np
T = 1000; beta = np.linspace(1e-4, 0.02, T); alpha = 1 - beta; abar = np.cumprod(alpha)
rng = np.random.default_rng(0); x0 = rng.uniform(-1, 1, size=200000)
x = x0.copy(); chk = {}
for t in range(T):
    x = np.sqrt(alpha[t]) * x + np.sqrt(beta[t]) * rng.normal(size=x.shape)
    if t + 1 in (100, 500, 1000): chk[t + 1] = x.copy()
for t, xs in chk.items():
    xc = np.sqrt(abar[t - 1]) * x0 + np.sqrt(1 - abar[t - 1]) * rng.normal(size=x0.shape)
    print(f"t={t:4d}: abar {abar[t-1]:.5f}  step-by-step std {xs.std():.3f} | closed form std {xc.std():.3f} | corr(x_t, x0) step-by-step {np.corrcoef(xs, x0)[0,1]:.3f}, closed form {np.corrcoef(xc, x0)[0,1]:.3f}")
```

```
t= 100: abar 0.89702  step-by-step std 0.633 | closed form std 0.635 | corr(x_t, x0) step-by-step 0.862, closed form 0.862
t= 500: abar 0.07859  step-by-step std 0.974 | closed form std 0.974 | corr(x_t, x0) step-by-step 0.169, closed form 0.163
t=1000: abar 0.00004  step-by-step std 1.000 | closed form std 0.999 | corr(x_t, x0) step-by-step 0.004, closed form 0.002
```

The two routes agree on the spread and the correlation with the clean data to within sampling error. By t = 1000 the cumulative factor is 0.00004 and the correlation with the original is 0.004: the data is gone and the sample is standard normal noise, which is the starting point of generation.

**Common weak answer.** "It denoises images step by step." It omits the forward process, the closed form and the cost of many sampling steps.

**Follow-up.** "How would you make sampling faster?" Fewer steps with a different sampler, or distillation; the sources read here do not cover them, so the answer should be marked as general knowledge to verify.

## 8. "Explain data parallelism and tensor (intra-layer) parallelism. What does each communicate?"

**What it tests.** Where the communication goes, and why some splits need no synchronisation.

**Reference answer.** Data parallelism replicates the model on every worker, gives each a different slice of the batch and averages the gradients before the update. [Goyal et al. (2017)](https://arxiv.org/abs/1706.02677) note that standard communication primitives such as allreduce perform summing, not averaging, so it is more efficient to fold the 1/k scaling into the loss (normalise the per-worker loss by the total minibatch size, not the per-worker size). The cost of the gradient exchange with a ring all-reduce algorithm is about 2(N-1)/N times the gradient size per worker, nearly independent of the number of workers. (The ring algorithm is not covered by the sources read here; the simulation below counts its traffic and checks its result.)

```python
import numpy as np
rng = np.random.default_rng(0)
def ring_allreduce(grads):
    n = len(grads); chunks = [np.array_split(g.copy(), n) for g in grads]; sent = 0
    for step in range(n - 1):                      # reduce-scatter
        for i in range(n):
            c = (i - step) % n; dst = (i + 1) % n; chunks[dst][c] = chunks[dst][c] + chunks[i][c]; sent += chunks[i][c].size
    for step in range(n - 1):                      # all-gather
        for i in range(n):
            c = (i + 1 - step) % n; dst = (i + 1) % n; chunks[dst][c] = chunks[i][c].copy(); sent += chunks[i][c].size
    return [np.concatenate(ch) for ch in chunks], sent / n
for n in (2, 4, 8, 64):
    G = [rng.normal(size=6400) for _ in range(n)]; out, per_worker = ring_allreduce(G)
    ok = all(np.allclose(o, sum(G)) for o in out)
    print(f"{n:3d} workers: correct sum {ok}; values sent per worker {per_worker:.0f} = {per_worker / 6400:.3f} x gradient size (2(N-1)/N = {2 * (n - 1) / n:.3f})")
```

```
  2 workers: correct sum True; values sent per worker 6400 = 1.000 x gradient size (2(N-1)/N = 1.000)
  4 workers: correct sum True; values sent per worker 9600 = 1.500 x gradient size (2(N-1)/N = 1.500)
  8 workers: correct sum True; values sent per worker 11200 = 1.750 x gradient size (2(N-1)/N = 1.750)
 64 workers: correct sum True; values sent per worker 12600 = 1.969 x gradient size (2(N-1)/N = 1.969)
```

The traffic per worker approaches twice the gradient size as the number of workers grows. Data parallelism alone needs the whole model on each worker, which is where the memory partitioning of Part 7, question 5 (ZeRO) comes in.

Tensor parallelism splits the matrices of a single layer across devices. [Shoeybi et al. (2019)](https://arxiv.org/abs/1909.08053) (Megatron-LM) describe an intra-layer approach that needs only a few communication operations inserted in native PyTorch, and train models up to 8.3 billion parameters on 512 GPUs with 76% scaling efficiency against their single-GPU baseline. In the MLP block `Y = GeLU(XA)`, they split A by columns, because that lets the nonlinearity act on each shard independently, while a row split needs a synchronisation point before the GeLU. A numeric check:

```python
import torch
torch.manual_seed(0); X = torch.randn(8, 16, dtype=torch.float64); A = torch.randn(16, 32, dtype=torch.float64)
gelu = torch.nn.functional.gelu; full = gelu(X @ A)
col = torch.cat([gelu(X @ A[:, :16]), gelu(X @ A[:, 16:])], 1)                  # split A by columns: no sync needed before GeLU
row = gelu(X[:, :8] @ A[:8]) + gelu(X[:, 8:] @ A[8:])                            # split A by rows: GeLU applied to partial sums
row_sync = gelu(X[:, :8] @ A[:8] + X[:, 8:] @ A[8:])                             # row split with a sum before GeLU
print(f"column split, GeLU on each shard: max diff from full {((col - full).abs().max()):.2e}")
print(f"row split, GeLU on each partial result then summed: max diff {((row - full).abs().max()):.2e}")
print(f"row split, sum first then GeLU: max diff {((row_sync - full).abs().max()):.2e}")
```

```
column split, GeLU on each shard: max diff from full 1.78e-15
row split, GeLU on each partial result then summed: max diff 5.95e+00
row split, sum first then GeLU: max diff 2.22e-15
```

The column split reproduces the full result with no communication before the nonlinearity. Applying GeLU to row-split partial results gives a different answer (difference 5.95), because GeLU(a + b) is not GeLU(a) + GeLU(b); the sum has to happen first.

**Common weak answer.** "Data parallelism splits the data; model parallelism splits the model." True and it stops before the communication pattern and the memory consequences.

**Follow-up.** "When does communication dominate?" When the interconnect is slow relative to the compute per step, which is why the choice of parallelism follows the hardware topology (the author's general statement).

## 9. "What is pipeline parallelism and what is the bubble?"

**What it tests.** Layer-wise partitioning and the cost of idle time.

**Reference answer.** Pipeline parallelism places consecutive groups of layers on different devices and passes activations between them. [Huang et al. (2019)](https://arxiv.org/abs/1811.06965) (GPipe) describe it as a library that allows scaling any network that can be expressed as a sequence of layers, with a batch-splitting algorithm giving almost linear speedup when a model is partitioned across multiple accelerators. A mini-batch is split into M micro-batches so that all K stages are busy at once. The idle time per accelerator, which the paper calls the bubble overhead, is O((K-1)/(M+K-1)), and in their experiments the bubble was negligible when M >= 4 x K. The communication is low because only the activations at the partition boundaries are passed.

A simulation of the forward schedule, in which stage k handles micro-batch m at time slot k + m, counts the idle slots:

```python
def gpipe_forward_idle(K, M):
    T = K + M - 1; busy = K * M; return 1 - busy / (K * T)
for K in (4, 8):
    for M in (1, 4, 16, 32):

```

The cost of more micro-batches is smaller matrix operations per step and, in practice, more activation memory to manage; GPipe's answer to the memory is re-computation, which the sources read here mention but this post does not test.

**Common weak answer.** "Pipeline parallelism puts different layers on different GPUs." It omits the micro-batches and the bubble, which are the substance.

**Follow-up.** "How do you choose between data, tensor and pipeline parallelism?" Data parallelism while the model fits; tensor parallelism inside a node with fast links, because it communicates in every layer; pipeline parallelism across nodes, because it communicates only at the stage boundaries; and the three combine. (The author's rule of thumb; the sources read here describe each method separately and report that Megatron-style intra-layer parallelism is complementary to pipeline parallelism.)

## 10. "How do you make Transformers cheaper? FlashAttention and mixture of experts."

**What it tests.** Two different kinds of saving: one that changes memory traffic and keeps the result exact, and one that changes the architecture.

**Reference answer.** [Dao et al. (2022)](https://arxiv.org/abs/2205.14135) observe that self-attention has quadratic time and memory in sequence length, and that approximate attention methods often fail to give wall-clock speedups. Their argument is that attention algorithms should be IO-aware, accounting for reads and writes between levels of GPU memory. FlashAttention is an exact attention algorithm that uses tiling to reduce reads and writes between GPU high-bandwidth memory and on-chip SRAM, requires fewer high-bandwidth-memory accesses than standard attention, and gives a 15% end-to-end wall-clock speedup on BERT-large (sequence length 512) against the baseline they report. The core trick is an online softmax: process the keys and values in blocks while keeping a running maximum and running denominator for each row, rescaling the partial output when the maximum changes.

```python
import numpy as np
rng = np.random.default_rng(0); n, d, B = 1024, 64, 128
Q, K, V = (rng.normal(size=(n, d)) for _ in range(3)); S = Q @ K.T / np.sqrt(d)
P = np.exp(S - S.max(1, keepdims=True)); ref = (P / P.sum(1, keepdims=True)) @ V
O = np.zeros((n, d)); m = np.full(n, -np.inf); l = np.zeros(n)         # running max, running denominator
for j in range(0, n, B):                                               # loop over key/value blocks; never builds the n x n matrix
    s = Q @ K[j:j+B].T / np.sqrt(d); m_new = np.maximum(m, s.max(1)); p = np.exp(s - m_new[:, None])
    scale = np.exp(m - m_new); l = l * scale + p.sum(1); O = O * scale[:, None] + p @ V[j:j+B]; m = m_new
O /= l[:, None]
print(f"tiled online softmax vs standard attention: max diff {np.abs(O - ref).max():.2e}")
print(f"largest score block held at once: {n}x{B} = {n * B:,} values vs full matrix {n}x{n} = {n * n:,} ({n / B:.0f}x smaller)")
```

```
tiled online softmax vs standard attention: max diff 3.89e-16
largest score block held at once: 1024x128 = 131,072 values vs full matrix 1024x1024 = 1,048,576 (8x smaller)
```

The blockwise result matches standard attention to 4e-16, so nothing is approximated, and the score matrix is never held in full. (This NumPy version shows the arithmetic; the speedup in the paper comes from how the GPU kernel uses on-chip memory, which this CPU code does not measure.)

[Fedus et al. (2022)](https://arxiv.org/abs/2101.03961) take the other route. Mixture-of-experts models select different parameters for each incoming example, so the model is sparsely activated: a very large number of parameters at a constant computational cost per example. The authors say adoption had been hindered by complexity, communication costs and training instability, and the Switch Transformer simplifies the routing to a single expert per token (k = 1), reports pre-training speedups of up to 7x over T5-Base and T5-Large at the same computational resources, and trains large sparse models with bfloat16. The arithmetic for a toy layer shows the trade-off, and the routing problem: with an untrained router the tokens do not spread evenly across experts, so each expert has a capacity, and tokens over capacity are dropped.

```python
import torch, torch.nn as nn
torch.manual_seed(0); d, h, E, tokens = 512, 2048, 8, 4096
dense = 2 * d * h; moe = E * 2 * d * h + d * E
print(f"dense FFN params {dense:,}; Switch layer with {E} experts: {moe:,} params ({moe / dense:.1f}x), FFN multiply-adds per token unchanged ({dense:,}) plus router {d * E:,}")
router = nn.Linear(d, E); x = torch.randn(tokens, d) * 3
choice = router(x).argmax(1); counts = torch.bincount(choice, minlength=E)
print("tokens per expert (untrained router):", counts.tolist(), f"ideal {tokens // E}")
for cf in (1.0, 1.25, 2.0):
    cap = int(cf * tokens / E); dropped = (counts - cap).clamp(min=0).sum().item(); print(f"capacity factor {cf}: capacity {cap}, dropped tokens {dropped} ({dropped / tokens:.1%})")
```

```
dense FFN params 2,097,152; Switch layer with 8 experts: 16,781,312 params (8.0x), FFN multiply-adds per token unchanged (2,097,152) plus router 4,096
tokens per expert (untrained router): [574, 493, 552, 511, 469, 451, 534, 512] ideal 512
capacity factor 1.0: capacity 512, dropped tokens 124 (3.0%)
capacity factor 1.25: capacity 640, dropped tokens 0 (0.0%)
capacity factor 2.0: capacity 1024, dropped tokens 0 (0.0%)
```

The layer holds 8 times the parameters of the dense one while each token still passes through one expert's feed-forward network, so the multiply-adds per token are unchanged plus a small router. The price is memory and routing: with this untrained router the busiest expert gets 574 of 4,096 tokens against an ideal 512, and at a capacity factor of 1.0 about 3% of tokens overflow and are dropped, while a larger capacity factor removes the drops at the cost of padding. (The paper has a term for this, the capacity factor, and adds an auxiliary loss to balance the load; this toy uses a random router and measures only the imbalance.)

**Common weak answer.** "FlashAttention is an approximation of attention" or "MoE makes the model smaller." The first is exact; the second has more parameters, not fewer.

**Follow-up.** "What is the catch with MoE at serving time?" All the experts must be held in memory although only one is used per token (the author's inference from the parameter count above; the paper's stated difficulties are complexity, communication costs and training instability).

## Takeaways

- Q-learning is off-policy: it learns the greedy policy's values from exploratory data. Exploration is not optional: the greedy bandit agent found the best arm in 35% of runs, epsilon = 0.1 in 81%.
- Maximising over noisy estimates overestimates (+2.5 noise units for 100 actions); selecting with one estimate and evaluating with another removes it.
- PPO clips the probability ratio in the objective, with a minimum that only ignores changes that help.
- The reparameterisation trick gave 3.6 times lower gradient standard deviation than the score-function estimator in the test above.
- Diffusion trains with a closed-form noising step and samples with about a thousand evaluations.
- Parallelism choices are about communication: about 2x the gradient size per worker for ring all-reduce, activations only at pipeline boundaries, and a synchronisation inside every layer for tensor parallelism.
- FlashAttention is exact and saves memory traffic; mixture of experts adds parameters at constant compute per token.
